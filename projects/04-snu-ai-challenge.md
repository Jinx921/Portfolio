## Overview

스토리 문장 하나와 순서가 섞인 이미지 프레임 4장을 받아, 원래 시간 순서를 맞히는 과제입니다. 네 위치를 모두 맞혀야 정답인 Exact Match로 평가합니다. 저는 데이터 검증부터 분할, 모델 학습, 제출까지 전 과정을 진행했습니다.

| 핵심 수치 | |
|---|---|
| **최종 리더보드** | **0.81300** |
| 내부 검증 (Fold 0, 1,915개) | Exact Match 0.525 → 0.549 → 0.560 |

## Problem

- **과제** 4장의 순서 조합은 24가지입니다. 문장 속 시간 단서(before, then, finally 등)와 이미지 변화를 함께 봐야 합니다.
- **누수 위험** Train 이미지 38,140장 중 바이트가 같은 이미지가 여러 샘플에 반복돼, 무작위로 나누면 검증 점수가 부풀 수 있었습니다.
- **출력 쏠림** 작은 모델은 입력 순서 그대로(`[1,2,3,4]`)를 답하는 쏠림이 있었습니다.

## Approach

1. **데이터 검증 · EDA** 라벨 형식, 이미지 이름 규칙, 정답 순열 유효성을 검사하고, Test는 열지 않는 원칙으로 Train만 분석했습니다.
2. **데이터 누수 방지** 이미지 MD5로 같은 이미지를 공유하는 샘플을 한 묶음으로 만들고, 묶음이 fold 사이에 갈라지지 않으면서 24개 정답 클래스가 모든 fold에 있도록 나눴습니다. 팀 공통 `fold_assignments.csv`를 SHA-256 checksum과 함께 배포했습니다.
3. **모델 키우기** 대회 제공 Qwen2-VL-2B에서 쏠림을 없앤 프롬프트를 만들고, Qwen2.5-VL-7B → Qwen3-VL-8B로 키우며 LoRA(attention · MLP 7개 모듈, r=16)를 학습했습니다.
4. **정답 분포를 지키는 증강** 이미지 입력 순서를 섞고 정답을 함께 변환하되, 증강 후 24개 클래스 개수가 원본과 같도록 목표 정답을 먼저 배정했습니다.
5. **문제 형태 바꾸기** 순서를 문장으로 생성하는 대신 24개 순열 중 하나를 고르는 분류 head를 붙이고, 여섯 이미지 쌍의 선후를 맞히는 pairwise BCE(0.3배)를 더했습니다.
6. **최종 학습** Fold 0에서 가장 좋았던 레시피를 Train 전체 9,535개에 적용해 제출했습니다.

## Data Split

같은 이미지가 여러 샘플에 반복돼, 무작위로 나누면 학습에 쓴 이미지가 검증에도 들어가 점수가 부풀 수 있었습니다. 그래서 이미지 단위로 묶은 뒤 묶음째 fold를 나눴습니다. 전체 흐름은 [README](../README.md#04)의 다이어그램에 있습니다.

| 단계 | 내용 |
|---|---|
| 1. 중복 탐지 | Train 이미지 38,140장의 MD5를 계산해 바이트가 같은 이미지를 찾음 |
| 2. 샘플 묶기 | 같은 이미지를 하나라도 공유하는 샘플들을 한 묶음으로 연결 |
| 3. 묶음 단위 5-Fold | 묶음이 여러 fold로 갈라지지 않게 나누고, 24개 정답 순열이 모든 fold에 고르게 들어가도록 층화 |
| 4. 팀 공통 파일 | `fold_assignments.csv`를 SHA-256 checksum과 함께 배포해 팀원 모두 같은 fold로 실험 |

이렇게 나눈 Fold 0(1,915개)을 모든 실험의 공통 검증 세트로 썼습니다.

## Result

| 실험 (Qwen3-VL-8B, Fold 0) | Exact Match |
|---|---:|
| 생성형 LoRA | 0.5253 |
| 24-class head + 분포 보존 증강 | 0.5493 |
| **+ pairwise loss** | **0.5598** |

최종 레시피로 Train 전체를 학습해 제출했고, 최종 리더보드 **0.81300**을 기록했습니다.

정답을 문장으로 생성하던 방식을 24개 중 하나를 고르는 분류로 바꾼 것이 가장 크게 기여했고, 쌍별 선후 정보가 추가로 도움이 됐습니다.
